How a voice note gets checked

Every clip takes the same route through the engine, whichever door it came in by. Repeats leave early and cost nothing; new clips go to DetectifAI's Aletheia once, and our rules read its 4-second windows to find the fake seconds.

    When a group forwards the same clip simultaneously, the second request waits for the first and gets its answer, so Aletheia is called once.

  4. 4

    Re-compressed copy of a known clip?

    WhatsApp re-encodes every forward, so bytes change. An audio fingerprint (Chromaprint) still matches: re-encodes score 0.89 or more, different clips 0.71 or less, and we accept 0.80. This needs Chromaprint's fpcalc on the server; without it the bot warns at startup and only stops 1 and 2 catch repeats. If no stored clip has a similar length, the fingerprint is computed alongside the API call instead of before it.

    A close score isn't enough on its own: a fake swapped into a few seconds of a known clip still scores high overall. So the two clips are also lined up piece by piece (a diff). Only if no stretch of about 2 seconds or more differs is it the same clip.

  5. 5

    Ask Aletheia, once

    One REST call returns an overall verdict and scores for 4-second windows every 2 seconds. The Idempotency-Key is the audio's sha256, so a retry or a repeat within 24 hours is never charged twice.

    POST /v1/deepfake/detect2 credits / sretry on 429 / 503

  6. 6

    Decide the band

    Each window's own real/fake label is used, never a cut-off on its score. For an edited copy of a known clip, the diff counts as a second signal: a changed stretch where even one window came back fake becomes a marked AI part, and an edited copy is never shown green, at best “Unclear: edited copy”.

    Remember it

    Result, both sha256 hashes (file and decoded audio), fingerprint and the audio go into SQLite, so the next forward, or a re-encoded, sped-up or pitch-shifted copy of it, exits at stop 1, 2 or 4. Chats are stored only as a salted hash, to count how many chats a clip reached.

Live listen: the same check while a call is on speaker

The /live page sends the microphone as 0.1-second 16 kHz chunks to our server (WS /ws/live), which opens Aletheia's live stream with the API key, so the key never reaches the browser. Aletheia answers after about 5 seconds of speech, then every 10 seconds; the page turns green or red. On Stop, the final result for the whole call, with its 4-second windows, goes through the same verdict rules (stop 6) and is stored (stop 7) as a private check that never appears on the radar. Only seconds of speech are billed.

A bad clip never crashes the bot

Not enough speech (Aletheia's 422, not charged), out of credits (402), a failed download or a broken file all come back as a polite reply in the chat's language instead of an error.
