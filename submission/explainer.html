01 · The problem

The sneakiest fakes are a real voice with one sentence swapped in

A voice note “from the principal” or “from the society” lands in a family group. Most of it is a real recording. One sentence in the middle, “send ₹500 to this number by tonight”, was made by AI from about 10 seconds of the person's voice. People forward it in one tap; nobody in the group can run a deepfake detector.

10 s is enough

We cloned our own voices (with consent) from about 10 seconds of audio, with free models a gaming laptop can run.

The headline misses it

On our spliced clip Aletheia's overall verdict said real. Only its 4-second windows caught the fake sentence. Reading the windows is the core of our product.

Forwarding is easier than checking

The answer has to arrive where the clip is: inside the group, in the group's language, in a form people forward instead of the fake.

05 · The gates, one by one

Every clip passes cheap gates before it costs a credit

Viral audio is, by definition, the same clip arriving again and again, often re-compressed, renamed, trimmed or sped up. Each gate asks “have we already checked this?” in a different way, cheapest first. The first gate that says yes answers for free.

1

Telegram file id

What it checks: Telegram gives every file a permanent id that stays the same when the message is forwarded. We look it up before downloading or decoding anything.

Catches: the same forward in any chat. Misses: anything re-uploaded (a new file id).

0 creditsno download, no ffmpeg
2

File SHA-256 (exact bytes)

What it checks: the SHA-256 of the exact file we would send. The same hash is the Idempotency-Key for Aletheia.

Catches: the same file from anywhere: a Telegram clip that comes back through WhatsApp → Share. Misses: any change to the bytes.

0 credits~0.4 s in our test
3

Decoded-audio hash

What it checks: we decode the sound to plain 16 kHz mono samples and hash those, ignoring the container, tags and file name.

Catches: .ogg renamed .opus, WAV vs FLAC, a voice note inside a video. Misses: lossy re-encodes (the samples change), left to gate 4.

0 creditsworks even without a fingerprint tool
4

Audio fingerprint (Chromaprint) + diff

What it checks: a fingerprint describes how a clip sounds, one code per ~0.12 s. Stored clips of similar length are compared; similarity ≥ 0.80 and a piece-by-piece diff that finds nothing changed = the same clip.

Catches: WhatsApp, MP3 and AAC re-encodes, volume changes, trimmed ends. Safe: 0 hits in 612 pairs of different recordings.

0 credits0.6–0.9 s
5

Speed and pitch copies

What it checks: a copy sped up, slowed down, played “like a tape” or made higher or deeper. We undo the change with ffmpeg (at the length ratio, or a grid of semitones) and fingerprint again. Runs only if gates 1–4 missed.

Catches: 0.5–2× speed, ±6 semitones: 9 / 9 copies on the server. Times stay the original's.

0 credits~1.5 s
6

Aletheia: genuinely new audio

Only audio that no gate recognised reaches the API, after the diff (page 6) and the edge trim (page 8) have cut what we pay for. If no stored clip is between half and double the length, gates 4–5 are skipped and the fingerprint is made in parallel with the API call, so a new clip isn't slowed down.

2 credits / sminimum 20 (10 s)

06 · Edited copies and the fingerprint diff

A near-match is only a repeat if nothing was changed

A whole-clip similarity score is an average. Swap 3 seconds of a known clip for AI speech and the copy still scores ~0.9, so without a second check it would inherit the original's “real” verdict. The fingerprint diff lines the two clips up piece by piece, like a text diff for audio, and lists the seconds that don't match.

How the diff works

  • Every fingerprint frame (~0.124 s) of the new clip is compared with every frame of the stored one. Strong ~2 s diagonals are the candidate alignments: one for a plain copy, two or more around an insertion or a cut.
  • A frame is unmatched when it scores more than 0.24 below the pair's own median, so heavy compression, which lowers the whole clip evenly, doesn't count as an edit. Three or more unmatched frames in a row = changed; a gap in the stored clip between matched parts = cut.
  • Tested: 128 / 128 true copies called the same, 69 / 69 edits of ≥ 2 s found at the right seconds. 7 ms per diff.

What an edited copy costs now

Kind of editCostHow the answer is built
Copy of a clip we called 🔴 likely AI0 creditsMost of it is that AI audio, so it stays 🔴.
One cut (seconds removed)21 creditsA ~10 s excerpt around the cut point, so a tiny AI piece slipped in there is still heard; the original's result elsewhere.
One stretch replaced or inserted21 creditsA ~10 s excerpt around the change (10 s is the minimum price anyway) + the original's result elsewhere.
Several changes, change + cut, or a messy difffull priceThe whole clip, as a new check. “Messy” = the copy doesn't match almost perfectly outside the changes, or has stray unmatched bits where a hidden small edit could be.
Real API, 4 edited copies: 84 credits instead of 198, the same answers. The excerpt even caught a 2 s AI insert that the full check had missed: in a short excerpt the AI seconds weigh more. And 6 excerpts of real voices (Hindi, Kannada, English) gave 0 false alarms. An edited copy is never shown 🟢, and the reply says which seconds differ.

07 · Detection and the four bands

The headline said real. The 4-second windows found the fake.

One Aletheia REST call returns an overall verdict and a score for every 4-second window, one starting every 2 seconds. Cutting the audio into pieces ourselves would cost about 5× the credits, so we never do. We read the windows.

BandWhenWhat people read
🔴 Likely AIAletheia's overall verdict is fake“Likely AI-generated”, with a card that says the score is evidence, not proof.
🟠 Partly AIOverall real, but some seconds are covered by ≥ 2 overlapping fake windows“AI-sounding part: 10–14 s. Words may have been edited into a real recording.” Tap to hear exactly that part.
🟡 UnclearOne isolated fake window, under 10 s of speech, or an edited copy with nothing flagged“Too short or too mixed to tell. Ask the sender where it came from.” We don't guess.
🟢 No signsOverall real, no fake window“No signs of AI in the voice.” It checks the voice, not the claim.

Rules that came from testing

  • Read each window's own verdict, never a score threshold. A real Hindi window scored 0.883 and came back “real”: windows use their own threshold, not the overall 0.62.
  • Two overlapping windows, not one. A real fake sentence of 2 s or more always lands in two overlapping windows; one stray window is “unclear”, not orange.
  • The diff is a second, independent signal. A changed stretch with even one fake window on it becomes an AI part; any edit turns 🟢 into 🟡.

08 · Saving credits: edge silence

Silence is billed like speech, so we don't send it

We measured it: a 16.4 s clip cost 33 credits; the same clip with 10 s of silence (or quiet room noise) added cost 53. So dead air before the first word and after the last is cut from the copy we send. The stored, played and forwarded clip stays whole, and Aletheia's times are shifted back.

Real API, 2 s of room noise at both endsWhole clipSent trimmedAnswer
Spliced clip49 credits46🟠 12–16 s, the same 3 windows as the whole clip
Real Hindi voice (our hottest real clip)7570🟢 no signs, 0 fake windows (same)

Only trimmed when it saves ≥ 2 credits and ≥ 10.5 s remain (never pushes a clip into “unclear”), and only what is truly quiet (below −45 dBFS), so a distant or whispered voice is never cut. Stream copy: the audio is not re-encoded.

Tried and not built: cutting pauses in the middle (our voice notes are only 0–10 % pauses, and every cut adds a join that could look like a splice); stopping long clips after 10 s (works on clones, but a clip that is AI only at the start would be called AI throughout); speeding audio up to pay for fewer seconds (games the pricing, changes what the model hears). 09 · Live listen (added after a round-1 judge's question)

A call on speaker, checked while the voice talks

Phone or laptop micThe /live page records 16 kHz PCM in 0.1 s frames after everyone on the call agrees.
→
Our WebSocket relay/ws/live adds the API key on the server. The key is never in the browser or a URL.
→
Aletheia live streamFirst verdict after ~5 s of speech, updates every 5 s, billed per second of speech.
→
Light + timeline🟢/🟡/🔴 while talking; on Stop the full result goes to the same timeline page.

Problem

Through a speaker and a phone mic, 2–4 s of real speech came back “fake” (0.65–0.97). A score floor can't fix that: it moved from call to call.

Rule

AI only when ≥ 3 overlapping windows (≈ 8 s) are each ≥ 0.9 sure; 🔴 only after two confident updates in a row. Anything weaker is 🟡, never 🟢.

Result

5 real calls in English, Hindi and Kannada: never red (4 no signs, 1 unclear). A cloned voice: flagged at its seconds.

Why on speaker? Android and iOS don't let apps capture call audio. The live threat is a cloned caller, fake for far longer than 8 s; finding a short spliced sentence stays the job of file checks. A live check is private: never on the public radar.

12 · Honest limits

What it can't do yet

Small test set

Male voices only, one phone, one quiet room. No women's voices yet. The numbers are a start, not a benchmark.

Very short fakes

A 1–2 s AI piece is often missed: the rule needs two overlapping 4 s windows. The diff's “these seconds differ” can still point at it in an edited copy.

One-word swaps

An edit of about 1 s can still pass as the same clip and get its stored result (the diff's resolution is ~2 s). An edited copy is re-checked around the edit it finds; a messy match gets the whole clip.

Calls need a speaker

Android and iOS don't let apps capture call audio, and the speaker path adds noise; hence the stricter live rule.

Short clips

Under 10 s of speech we answer “Unclear” rather than guess.

Voice, not claim

A score is evidence, not proof, and a real person can still say something false. Every card says so.

14 · Questions judges may ask

Short, honest answers

Use of Aletheia

Why read the segments and not just Aletheia's verdict?
On our spliced clips the overall verdict said “real” 4 times out of 6. The 4 s windows caught the fake sentence every time. One REST call returns both, so reading the windows costs nothing extra.
Why not cut the audio into pieces and check each?
Aletheia already scores overlapping 4 s windows in one call. Cutting it ourselves would mean many calls, each with a 20-credit minimum: about 5× the cost for the same information.
How do you turn windows into “AI part: 10–14 s”?
Seconds covered by at least two overlapping fake windows. A real fake sentence of 2 s or more lands in two windows; one stray window is “unclear”.
Why not a score threshold like 0.62?
A real Hindi window scored 0.883 and Aletheia still called it real: windows use their own threshold. We read each window's verdict field.
Do you give anything back to DetectifAI?
Yes: every 👍/👎 goes to their feedback API with the operation id, including Hindi and Kannada examples.
REST or MCP?
REST in the product (multipart upload, retries, idempotency). The MCP server we used only to explore the API inside Claude Code.

Accuracy and honesty

How accurate is it on Indian voices?
On our own voice notes in English, Hindi and Kannada: 0 / 12 false alarms; clones 6 / 6 caught; splices 6 / 6 flagged. Small set, male voices only, so we present it as a sanity check, not a benchmark.
What happens with a false alarm?
We avoid strong claims: four bands including “unclear”, “a score is evidence, not proof” on every card, and 👎 to report it. The live rule was made stricter after we saw speaker false alarms.
Can a real person saying something false pass?
Yes. We check whether the voice is AI-made, not whether the claim is true. The 🟢 answer says exactly that.
What can't it detect?
AI pieces of 1–2 s often slip through; one-word swaps (~1 s) in a known clip can pass the diff; under 10 s of speech we say “unclear”.
Does it work in Kannada and Hindi?
Replies, cards and pages are in all three languages, and Kannada was as clean as English on our voices. Hindi ran hottest but stayed correct. DetectifAI's docs say the model is strongest in English and Hindi.

Credits and efficiency

What does one check cost?
2 credits per second, minimum 20. A 20 s voice note is about 41 credits. A repeat is 0.
What if the same fake is forwarded again, re-encoded or sped up?
Five gates recognise it for free: file id, exact bytes, decoded audio, fingerprint + diff, speed/pitch undo. 9 / 9 speed and pitch copies matched on the server.
Could the cache give a fake the verdict of a real clip?
That is why every fuzzy match must pass the diff: any stretch of ~2 s or more that differs makes it an edited copy, never a repeat. 0 wrong hits in 612 pairs; 69 / 69 edits caught.
And an edited copy, do you pay the full price again?
No. One changed stretch or one cut is a 10 s excerpt (21 credits); a copy of a 🔴 clip is free. Only when the match is clean; otherwise the whole clip. 4 copies: 84 instead of 198 credits, same answers.
Is silence billed?
Yes, we measured it. So edge silence is cut from the copy we send, in 2 s steps so the windows don't move, and only if it is truly quiet. Live listen is billed only for speech.
Doesn't a 10 s excerpt change the answer?
We tested it: on 4 edited copies the answers matched the full check or were better, and 6 excerpts of real voices gave 0 false alarms. The rest of the clip keeps the original's result, which was the same audio.

14 · Questions judges may ask (continued)

Credits (continued)

How do you show the savings?
The radar shows credits saved by repeats and edited copies, using DetectifAI's pricing.

Usefulness and design

Why Telegram and not WhatsApp?
WhatsApp has no bot API for groups. Telegram lets a bot sit in a group and answer in the thread. WhatsApp users reach us through Android's share sheet: one tap from the voice note.
Why a card image?
People forward images more readily than links. The card is the thing you forward instead of the fake, and it reads correctly in Kannada and Hindi.
Who is this for, really?
Family and college groups where “official” voice notes spread, the admins of those groups, and anyone who gets a “it's me, send money” call.
What is the AI-clip radar for?
It shows which flagged clips are going round right now (seen in ≥ 2 chats or checked ≥ 3 times this week), so a group admin can warn people early.
How fast is it?
A new clip takes about as long as the Aletheia call; a repeat is answered in under a second; a card renders in ~90 ms.

Live calls

Does it work on live calls?
Yes, with the call on speaker next to the /live page, through Aletheia's live stream. Phones don't let apps capture call audio directly.
Why is the live rule so strict?
Through a speaker, 2–4 s of real speech can look fake (0.65–0.97). A cloned caller is fake for much longer, so we need ≈ 8 s of confident windows before saying AI. 5 real calls: never red.
Is the other person's consent needed?
Yes. The page asks the user to get everyone's agreement before Start; live checks are private and never on the radar.

Privacy and safety

What do you store?
The result, the audio file (for the timeline), a fingerprint, and chats only as salted hashes for the radar. No names, phone numbers or message text. The bot deletes its download right after the check. For real use we'd add an expiry for stored audio.
Where is the API key?
Only on our server, in .env. Live listen goes through our relay, so the key is never in the browser or a URL.
Whose voices did you clone?
Only our own, with consent, for testing. No public figures.

Engineering

How do you test without spending credits?
150 automated tests on recorded real Aletheia replies. Real calls only for a step's final check, on a separate database, with the cost said first.
What happens if Aletheia is down or slow?
Retries with backoff reuse the same Idempotency-Key, so a retry is never charged twice; errors become a clear “couldn't check” reply, never a crash.
Can it scale?
Viral audio is mostly repeats, which are free and fast, so cost grows with new clips, not with forwards. SQLite and one process are enough for a demo; a hosted DB and a queue are the next step.
What would you build next?
Check only the changed seconds in more edit shapes, an English transcript check for one-word swaps, a larger test set with women's voices, audio expiry, and early stop for long fully-cloned clips.
What was the hardest part?
Not trusting averages: the overall verdict hid splices, the fingerprint score hid edits, and a 1.84 s trim moved the windows. Each time the fix was to look at the pieces.
